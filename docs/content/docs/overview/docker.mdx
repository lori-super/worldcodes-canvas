# Docker Deployment

## Build the static frontend

```bash
cd /path/to/worldcodes-canvas
docker compose up -d --build
```

This builds the `worldcodes-canvas` container only from current source and never pulls another project's prebuilt image. Open `http://localhost:3000`.

Or build it directly:

```bash
docker build -t worldcodes-canvas:local .
docker run --rm -p 3000:3000 worldcodes-canvas:local
```

## Important boundary

The root image contains only the Vite static frontend, not WorldCodes Relay. It is suitable for interface preview. Full production generation also requires:

- Same-origin Caddy routes for approved `/v1/*` and `/v1beta/*` requests.
- Relay model routing and user authentication.
- A private temporary R2 bucket for MiniMax H3 references.

The audited production contract is under `deploy/worldcodes/`. Never place provider API keys inside the static container.

## Data

Canvases, assets, generation history, and the prompt cache remain in browser IndexedDB, so the static container needs no persistent volume. The production prompt library contacts only fixed read-only JSON sources, and local reference bytes go directly to temporary R2 only when generation requires it.

## Standalone documentation

```bash
cd docs
docker compose up -d --build
```

The Next.js documentation service is separate and does not include the model Relay.
